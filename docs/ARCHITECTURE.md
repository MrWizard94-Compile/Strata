# Engine architecture and decisions

STRATA is an original Rust voxel engine/game under active development. This document describes the implemented foundation and its extension boundaries. The complete delivery plan is in [PROJECT-TRACKER.md](PROJECT-TRACKER.md).

## Current execution path

`winit ApplicationHandler → input/UI → fixed 60 Hz player tick → bounded CPU meshing workers → main-thread GPU uploads → wgpu world pass → egui overlay → surface presentation`.

The player and world edits are owned by the application thread. Worker jobs share immutable `Arc<World>` snapshots. An edit uses copy-on-write, invalidates a conservative neighbour region and increments a mesh revision. Results from earlier revisions are discarded. Queues are bounded to twice the worker count. Admission allows up to two callbacks, 4 MiB of packed-quad payload and 2 ms of CPU time per redraw. Each callback copies at most the remaining byte budget, rounded down to one 8-byte quad, and cannot be interrupted. The destination buffer is allocated before that timed copy. A larger mesh continues on later redraws and stays hidden until its last slice. The previous visible mesh stays on screen until the replacement completes. A newer revision, an unload or shutdown abandons that partial upload. There is no oversized exception. One deferred result retains ownership and is revalidated on retry. See STREAMING.md. Workers use a shared receive lock only to take a job, then mesh independently; this is not described as lock-free. An adapter without 16-byte immediates stops at startup with a readable error. Vulkan and Direct3D 12 on the GTX 1660 Ti provide that feature.

`World` is a seed plus sparse edits. Terrain is a pure function of that seed and integer coordinates: layered value noise shapes rolling plains, hills, forests, deserts, oceans and beaches; water fills a fixed sea level; grass, dirt, sand and stone form the surface; noise tunnels carve caves that keep a solid seal under oceans and beaches; trees and coal, iron, gold and diamond veins are anchored on global grids so chunk borders and worker order cannot change them. A 32³ chunk samples a one-block halo, generates exposed faces and greedily merges compatible material/AO faces. A block ID is one byte in the sampled working buffer; mesh storage, scratch arrays, edits and GPU buffers are additional costs. This is conventional greedy meshing, not the roadmap's binary bitmask mesher.

Rendering uses native wgpu 30, depth-tested mesh buffers, CPU frustum culling, directional lighting, per-corner ambient occlusion, atmospheric sky/fog, seventeen original 32×32 sRGB material tiles, stylized reflective water and a selected-block outline. Terrain is drawn as instanced 8-byte quads (`draw(0..6, 0..quad_count)`) plus a 16-byte chunk-origin immediate. Each quad stores a chunk-local position, size, axis, winding, four AO corners, texture layer, lighting variation and a water bit. The fragment shader rebuilds world-axis tile UVs from the interpolated world position. A separate vertex-only uniform supplies the historical brightness bits, leaving the camera uniform for view and atmosphere parameters. The 44-byte logical corner remains the digest and material-test representation; it is not uploaded. A 20-minute day/night cycle advances on the same 60 Hz tick while playing and pauses with the game. That fraction drives the sun direction plus sky, fog, and ambient colors through appended camera-uniform fields. The packed-quad layout is independent of the cycle. Night ambient stays dark blue and above black so the world remains readable. A texture array isolates materials. Face-specific layers distinguish grass and timber ends. Six mips average in linear light, with nearest magnification and filtered minification. Brightness is lighting, not a second albedo palette. Water remains visually opaque and non-solid. The device requires `Features::IMMEDIATES`. Camera-relative rendering is not implemented: the shader still adds the chunk origin in f32. Global illumination, true fluid simulation, GPU visibility/indirect submission, LOD and physical construction are future phases.

Save schema 1 / generator 2 stores seed, sorted sparse edits, player state, and time of day. Time of day is a fraction in `[0, 1)` with midnight at 0. A generator 2 save written before that field existed still loads; the missing value defaults to 08:00. Non-finite or out-of-range times are rejected and the file is preserved. Generator 1 is pre-release and is not migrated: those files are rejected with a player-facing explanation and left untouched. Unedited terrain is not silently reinterpreted. Two alternating slots retain the preceding committed generation during replacement. A flushed pending file is renamed to the inactive slot; the active slot is retained. Unsupported versions, oversized saves, unknown block IDs, duplicate edits and non-finite/out-of-range player states are rejected. A corrupt slot stops loading with an explicit error, preserving it for recovery. This protects common interrupted writes; it is not a filesystem power-loss durability proof. Generator 1 was dropped without a migration because no world had been released. A later released format must migrate or preserve old worlds, not silently regenerate them under changed terrain rules.

`SaveStore` holds an OS-exclusive lock for its lifetime. A second writer is rejected; a leftover empty lock marker is harmless once the process closes. Controlled rendering and event-loop failures attempt a CPU-world save before teardown and retain failure diagnostics. The launcher captures those diagnostics under `logs/`; unexpected process termination/panic is not claimed to invoke this controlled-save path.

New spawn and fall recovery search upward for a nonintersecting full-body AABB, including trees and edits. Search is bounded at eye height 512; if construction fills the recovery column, creative flight provides escape. Turning flight off while intersecting terrain is rejected with feedback.

Presentation telemetry counts only calls that reach `Queue::present`; skipped acquisitions are separately counted. Intervals measure CPU-observed presentation-submission cadence, not GPU execution or physical display timing. The 240-sample window resets on entering/resuming. Skipped/unfocused rendering retries are throttled; minimized windows wait for events.

## Decisions and reversal paths

| Decision | Reason | Consequence / reversal |
|---|---|---|
| Direct wgpu + winit; egui UI | Engine is the director's central goal; direct visibility into GPU resources and platform behavior | More integration work than a complete game engine. Keep world/simulation APIs independent so renderer can evolve. |
| Rust 1.97.1 and exact current primary dependency versions | Compile against one declared, reproducible graph; verify current APIs from installed source | Lockfile must accompany source. Updates need integration, shader and native tests. |
| 32-block chunk edge | Moderate edit/remesh unit and initial memory budget | Benchmark before changing; storage coordinates/save semantics remain world-block based. |
| Conventional greedy meshing first | Establish an independently testable geometry baseline | Binary meshing is admitted only after equivalent material/AO/edge output and measured benefit. |
| 8-byte quad instances and a chunk-origin immediate | The 44-byte corner plus indices made one checkerboard chunk 19,660,800 bytes; one 2026-10-20 callback spent 7.1273 ms | Positions stay chunk-local so a later camera-relative pass can move the origin without rewriting buffers. Reversal is to upload expanded corners if a device lacks immediates or a visual difference appears. |
| Bounded workers, immutable snapshots | Explicit ownership, cancellation by revision and no mutable shared world | Large edit maps can make snapshots expensive; measure copy-on-write and move toward per-chunk versions if needed. |
| Fixed simulation tick, independently rendered frames | Stable collision update order and responsive presentation | Presently player and the day clock; no claim of deterministic whole-world simulation or full interpolation. |
| 20-minute day on that tick | One cheap clock that pauses with play and survives in the existing save | Sun, sky, fog, and ambient are uniforms. Retune `DAY_LENGTH_SECONDS` without a schema bump. |
| Original procedural assets | Coherent early visual foundation without copying protected game assets | Art direction, animation, sound and material authored detail require dedicated later phases. |
| Windows first, GTX 1660 Ti measured first | Real available acceptance machine | Vulkan/DX12 backend availability does not establish Xbox compatibility; console evidence is a separate stage. |

## Known architectural limits to address

- Quad positions are chunk-local and the chunk origin is a per-draw immediate, which is a cheap place for a later camera anchor. The shader still evaluates `f32(origin) + f32(local)`. Far-coordinate precision and camera-relative rendering are not done.
- Vertically streamed chunks currently span -32 through 159. Editing is constrained to -30 through 158. Large or unbounded vertical construction is not yet supported.
- The sparse edit limit is 100,000 and encoded save size is 16 MiB. These are explicit safety bounds for schema 1, not the final creative-world capacity.
- Collision samples procedural terrain directly. Dense entity populations need chunk/collider caching and measured invalidation.
- All edits globally invalidate in-flight revisions. This is correct but can waste work under rapid editing; per-region generations and priority lanes need measurement.
- Terrain generation is a pure function of the seed and integer coordinates. Height and value noise use IEEE-754 `f64` add, multiply, and divide, with explicit floor and half-away rounding so the generator does not call libm `floor`, `round`, `sin`, `exp`, or `pow`. Rust does not contract those multiplies into FMA unless a non-default fast-math flag is set. Chunk bytes for seed `20261021` are pinned by FNV-1a-64 golden hashes in `src/world.rs` (`golden_chunks_match_platform_independent_hashes`). A mismatch on unchanged generator code means cross-platform drift; refresh those digests only for an intentional generator change, using the actual values printed by that test. The pin is evidence when CI runs it, including Windows. It does not prove bit-identical output on untested CPUs or with fast-math flags. Raycasts still use `sqrt` and `floor`, and material authoring uses `powf`; neither feeds chunk bytes.
- No ECS, multiplayer, mod sandbox, machines, ecology, progression or authored content loop is currently implemented. Do not present crate names as evidence of these systems.

## Research and acceptance discipline

The supplied roadmap's exact timings are unverified targets, not measurements of this engine. `64³ × 2 bytes = 512 KiB` before overhead, so its 256 KB dense-u16 chunk figure is inconsistent. A radius measured in chunks needs an explicit edge size. A 60 Hz tick alone does not establish deterministic simulation. Wasm fuel, epoch interruption, memory limits, host-call validation and crash recovery are separate mechanisms.

Every material performance experiment must record commit, build profile, seed, region, camera path, edits, resolution, quality, GPU/driver, warm/cold state and percentile frame times. CPU meshing microbenchmarks cannot establish total render latency or Xbox frame rate. Pitch claims require measured operation on the hardware claimed.
