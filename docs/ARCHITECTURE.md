# Engine architecture and decisions

STRATA is an original Rust voxel engine/game under active development. This document describes the implemented foundation and its extension boundaries. The complete delivery plan is in [PROJECT-TRACKER.md](PROJECT-TRACKER.md).

## Current execution path

`winit ApplicationHandler → input/UI → fixed 60 Hz player tick → bounded CPU meshing workers → main-thread GPU uploads → wgpu world pass → egui overlay → surface presentation`.

Walking acceleration, friction, coyote time, and jump buffering run inside that fixed tick. A rendered frame only decides how many ticks catch up, and each of those ticks receives the same sampled input and `dt` of 1/60 s. The day clock advances after the player tick in that same loop.

## Player collision sweep

The walking body is an axis-aligned box: 0.3 m half-width, feet 1.6 m below the eye, head 0.15 m above. It does not rotate, and it only collides with grid-aligned solid voxels. Flight skips the sweep.

Each walking tick applies acceleration and gravity, then sweeps the remaining displacement:

1. For each axis that still moves, walk the voxel planes its leading face will cross. At a plane, test the cells that face covers, with the other two axes already advanced to that same time. A solid cell is a hit. A body already inside a solid does not count as a new impact and is not pushed back out; further motion into that solid stops, and motion back out is allowed.
2. Advance all three axes to the earliest hit, then stop `1.0e-4` m short of the plane. Zero that axis's velocity and its leftover displacement. A downward hit marks the body grounded.
3. Repeat with whatever displacement remains. After four contacts, drop the rest and zero any velocity that still carried it, so the next tick cannot retry a move this tick refused to finish.

Equal times use a fixed order: floor, then X, then Z, then a ceiling. Sneak adds a footing test on the same sweep, and a horizontal plane that would leave the supporting cells stops that axis. A landing that started in the air uses that same footing hold for the remainder of the landing tick only. Later ticks can walk off the lip unless sneak is still held.

The sweep degrades in a few known ways. It has no rotational component and no collider that is not a grid cell. An overlap that already exists is left where it is. More than four contacts in one tick discards the tail of the move. A single axis query stops after 96 empty planes rather than skipping them. The discrete "am I inside a block?" test still insets the box by 0.001 m, separate from the 0.0001 m sweep gap, so a face the sweep stopped short of is not reported as a penetration. Unit tests call `Player::tick` directly; they do not drive `Game::redraw`.

The player and world edits are owned by the application thread. Worker jobs share immutable `Arc<World>` snapshots. An edit uses copy-on-write, invalidates a conservative neighbour region and increments a mesh revision. Results from earlier revisions are discarded. Queues are bounded to twice the worker count. Admission allows up to two callbacks, 4 MiB of payload and 2 ms of CPU time per redraw; one oversized first mesh may run alone to avoid starvation, and an active callback cannot be interrupted. One deferred result retains ownership and is revalidated on retry. See STREAMING.md for measured costs and the remaining segmented-upload work. Workers use a shared receive lock only to take a job, then mesh independently; this is not described as lock-free.

`World` is a seed plus sparse edits. Terrain is a pure function of that seed and integer coordinates: layered value noise shapes rolling plains, hills, forests, deserts, oceans and beaches; water fills a fixed sea level; grass, dirt, sand and stone form the surface. Cold grass, and cool ground at height 41 or above, carries one block of snow above the surface. On seed 20261021 that cutoff is the 97th percentile of a 231,361-column sample (about the top 3.4%); height 47 never occurs. The height-46 columns in that area are warm and stay bare. Shallow beaches and seabeds grow clay patches; deep ocean and desert stay sand. Noise tunnels carve caves that keep a solid seal under oceans and beaches. Trees and coal, iron, gold and diamond veins are anchored on global grids so chunk borders and worker order cannot change them. Rare crystal clusters sit in stone from y 2 through 14, and basalt intrusions sit in stone from y 1 through 8, in addition to the solid basalt floor at y less than 1. Snow, clay, crystal and basalt use the same integer hashes as the ores. They do not call libm. A 32³ chunk samples a one-block halo, generates exposed faces and greedily merges compatible material/AO faces. A block id is a `u16` index into the frozen registry (`BlockId`). The halo and the generated chunk store that id. Mesh vertices store a texture layer, lighting color, and linear tint, not the block id. The mesher reads a dense per-id table on `World` (solid bit, replaceable bit, render class, face layer, and tint) built once when the world is created. Each mesh copies the solid bit, the replaceable bit, and the render class into one flag byte per halo cell. The face and occlusion loops read that byte and do not look up the block id. Halo sampling uses the same per-id table for replaceable cells. This is conventional greedy meshing, not the roadmap's binary bitmask mesher.

Builtin blocks are TOML files under `assets/strata/blocks/`, loaded by the same parser a data mod's files will use. The id is the path (`assets/strata/blocks/stone.toml` is `strata:stone`), not a field in the file. `src/registry.rs` owns the only TOML parser. The normal path embeds those files in the binary. `--data-dir <data-root>` or `STRATA_DATA_DIR` opts into a folder, used as given, joined only with `assets/strata/blocks`. The working directory is not searched. Files that are not `.toml` are ignored, and CRLF line endings are accepted. Load order is the fixed `BUILTIN_FILES` list, so runtime ids 0 through 15 match the old schema-1 numbers and `strata:missing` is 16. Those order checks run in release builds as well as debug. After load, definitions are immutable. Worldgen resolves `strata:stone` and the other builtin names once in `World::new` and then compares ids. Fluid faces are chosen by `RenderClass::Fluid`, not by a water enum match. Leaves are `cutout` in the file. Until the cutout pipeline exists, the mesher culls cutout blocks like opaque ones, so canopy faces stay as they are today. `render = "translucent"` is a parse error, not a `RenderClass` variant, until a translucent pass exists, because culling still keys off solidity. Vertex alpha is `0.72` for fluid and `1.0` otherwise, which is what the current shader uses to recognize water. Block `tint` defaults to identity white, is stored as a vertex attribute, and is the shader multiply. The hotbar uses a separate `swatch`. Fluid tint alpha must be 1.0; it is not the water signal. Texture references may contain path segments (`strata:block/grass_top`). Each segment is `[a-z0-9_]+`. A block file larger than 64 KiB is rejected from its length before the parser reads past that limit. Grass top, water tint, stone's north rotation, and air's name key are load errors that name the file and the key. A bad command-line argument and a panic write `strata-error.txt` beside the executable; a successful start removes a stale copy. A reference with no authored tile uses the one `strata:missing` checker and warns with the file and the key. The client also writes `strata-registry-warnings.txt` beside the executable and deletes it when a later start has no warnings. The frozen array rejects more than 256 layers. Variant lists are not packed into one contiguous layer run; that stays for a later change. Cardinal face keys are `north`, `south`, `east`, and `west` (outward normals −Z, +Z, +X, and −X). Precedence is `all`, then `side` for the four cardinals, then the specific face.

Rendering uses native wgpu 30, depth-tested mesh buffers, CPU frustum culling, directional lighting, per-vertex ambient occlusion, atmospheric sky/fog, the original 32×32 sRGB material tiles plus a magenta/black checker for `strata:missing`, stylized reflective water and a selected-block outline. Array-layer numbers are assigned when the registry freezes, in sorted texture-id order, and are not written in the TOML. The seventeen authored tiles keep their previous pixels; the grain salt still uses the historical authoring index. A 20-minute day/night cycle advances on the same 60 Hz tick while playing and pauses with the game. That fraction drives the sun direction plus sky, fog, and ambient colors through appended camera-uniform fields. The vertex layout is independent of the cycle. The terrain vertex is 60 bytes: position, normal, lighting color, texture layer, and linear tint at location 4. The shader multiplies albedo by that tint. Identity-white builtin tints leave the tiles unchanged. Night ambient stays dark blue and above black so the world remains readable. A texture array isolates materials; world-axis coordinates repeat one tile per block across merged quads. Face-specific layers distinguish grass and timber ends. Six mips average in linear light, with nearest magnification and filtered minification. Vertex RGB carries lighting variation, not a second albedo palette. Water remains visually opaque and non-solid. Global illumination, true fluid simulation, GPU visibility/indirect submission, LOD and physical construction are future phases.

Save schema 1 / generator 3 stores seed, sorted sparse edits, player state, time of day, an eight-slot hotbar, and the selected slot. Edit and hotbar numbers are still the builtin ids `0..=15`. Names live in the block files, not in this document. A per-world name palette is the next save change and is not in schema 1. Time of day is a fraction in `[0, 1)` with midnight at 0. `time_of_day`, `hotbar`, and `selected_slot` are optional on that one document: a generator 3 file that omits them loads at 08:00, with the default materials and slot 0. JSON null, unknown fields, non-finite or out-of-range times, unknown block ids, non-placeable ids, and a slot outside 0–7 are rejected and the file is preserved. Generator 1 and generator 2 saves are rejected and left untouched. A generator newer than 3 is rejected with a player-facing explanation and left untouched. Unedited terrain is not silently reinterpreted. Two alternating slots retain the preceding committed generation during replacement. A flushed pending file is renamed to the inactive slot; the active slot is retained. Unsupported versions, oversized saves, unknown block IDs, duplicate edits and non-finite/out-of-range player states are rejected. A corrupt slot stops loading with an explicit error, preserving it for recovery. This protects common interrupted writes; it is not a filesystem power-loss durability proof. Generators 1 and 2 were dropped without a migration because no world had been released. A later released format must migrate or preserve old worlds, not silently regenerate them under changed terrain rules.

`SaveStore` holds an OS-exclusive lock for its lifetime. A second writer is rejected; a leftover empty lock marker is harmless once the process closes. Controlled rendering and event-loop failures attempt a CPU-world save before teardown and retain failure diagnostics. The launcher captures those diagnostics under `logs/`; unexpected process termination/panic is not claimed to invoke this controlled-save path.

New spawn and fall recovery search upward for a nonintersecting full-body AABB, including trees and edits. Search is bounded at eye height 512; if construction fills the recovery column, creative flight provides escape. Turning flight off while intersecting terrain is rejected with feedback.

Presentation telemetry counts only calls that reach `Queue::present`; skipped acquisitions are separately counted. Intervals measure CPU-observed presentation-submission cadence, not GPU execution or physical display timing. The 240-sample window resets on entering/resuming. Skipped/unfocused rendering retries are throttled; minimized windows wait for events.

## Decisions and reversal paths

| Decision | Reason | Consequence / reversal |
|---|---|---|
| Direct wgpu + winit; egui UI | Engine is the director's central goal; direct visibility into GPU resources and platform behavior | More integration work than a complete game engine. Keep world/simulation APIs independent so renderer can evolve. |
| Rust 1.97.1 and exact current primary dependency versions | Compile against one declared, reproducible graph; verify current APIs from installed source | Lockfile must accompany source. Updates need integration, shader and native tests. |
| 32-block chunk edge | Moderate edit/remesh unit and initial memory budget | Benchmark before changing; storage coordinates/save semantics remain world-block based. |
| Conventional greedy meshing first | Establish an independently testable geometry baseline | Binary meshing is admitted only after equivalent material/AO/edge output and measured benefit. |
| Bounded workers, immutable snapshots | Explicit ownership, cancellation by revision and no mutable shared world | Large edit maps can make snapshots expensive; measure copy-on-write and move toward per-chunk versions if needed. |
| Fixed simulation tick, independently rendered frames | Stable collision update order and responsive presentation | The simulation tick drives the player, the day clock, and repeat edits. A frame that drains zero ticks does not cancel a held edit. No claim of deterministic whole-world simulation or full interpolation. |
| 20-minute day on that tick | One cheap clock that pauses with play and survives in the existing save | Sun, sky, fog, and ambient are uniforms. Retune `DAY_LENGTH_SECONDS` without a schema bump. |
| Original procedural assets | Coherent early visual foundation without copying protected game assets | Art direction, animation, sound and material authored detail require dedicated later phases. |
| Block definitions are data, ids are `u16` | Vanilla content loads the way a data mod will. Schema 1 numbers stay the builtin order. | Adding a block is a TOML file plus a loader entry, not an enum edit. Schema 2 will store names. Reordering `BUILTIN_FILES` would change saves and the golden chunks. |
| Windows first, GTX 1660 Ti measured first | Real available acceptance machine | Vulkan/DX12 backend availability does not establish Xbox compatibility; console evidence is a separate stage. |

## Known architectural limits to address

- World mesh coordinates use f32; far-coordinate precision is not yet premium large-world behavior. Camera-relative geometry and integer spatial authority are a planned S2 contract.
- Vertically streamed chunks currently span -32 through 159. Editing is constrained to -30 through 158. Large or unbounded vertical construction is not yet supported.
- The sparse edit limit is 100,000 and encoded save size is 16 MiB. These are explicit safety bounds for schema 1, not the final creative-world capacity.
- Collision samples procedural terrain directly. Dense entity populations need chunk/collider caching and measured invalidation.
- All edits globally invalidate in-flight revisions. This is correct but can waste work under rapid editing; per-region generations and priority lanes need measurement.
- Terrain generation is a pure function of the seed and integer coordinates. Height and value noise use IEEE-754 `f64` add, multiply, and divide, with explicit floor and half-away rounding so the generator does not call libm `floor`, `round`, `sin`, `exp`, or `pow`. Rust does not contract those multiplies into FMA unless a non-default fast-math flag is set. Chunk bytes for seed `20261021` are pinned by FNV-1a-64 golden hashes in `src/world.rs` (`golden_chunks_match_platform_independent_hashes`). A mismatch on unchanged generator code means cross-platform drift; refresh those digests only for an intentional generator change, using the actual values printed by that test. The pin is evidence when CI runs it, including Windows. It does not prove bit-identical output on untested CPUs or with fast-math flags. Raycasts still use `sqrt` and `floor`, and material authoring uses `powf`; neither feeds chunk bytes.
- No ECS, multiplayer, mod sandbox, machines, ecology, progression or authored content loop is currently implemented. Do not present crate names as evidence of these systems.

## Research and acceptance discipline

The supplied roadmap's exact timings are unverified targets, not measurements of this engine. `64³ × 2 bytes = 512 KiB` before overhead, so its 256 KB dense-u16 chunk figure is inconsistent. A radius measured in chunks needs an explicit edge size. A 60 Hz tick alone does not establish deterministic simulation. Wasm fuel, epoch interruption, memory limits, host-call validation and crash recovery are separate mechanisms.

Every material performance experiment must record commit, build profile, seed, region, camera path, edits, resolution, quality, GPU/driver, warm/cold state and percentile frame times. CPU meshing microbenchmarks cannot establish total render latency or Xbox frame rate. Pitch claims require measured operation on the hardware claimed.
